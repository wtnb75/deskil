# deskil 版と通常版のトークン比較ベンチ（B-014）

deskil は「手順を守らせ、トークンを減らす」ことを狙っている。この文書は、その効果を測る手順と、結果の記録欄である。

## 方針

- 題材は変換済みの 1 スキル（`deskil-dev:decide`）。他の機能を足す前に効果を見たい、という元の狙いに合わせて小さく始める。
- 計測はセッション記録（jsonl）の集計。スクリプトは `shared/bench/tokens.py`。
- 試行は通常版・deskil 版とも各 3 回。
- 指標は、トークン数、手順の遵守、失敗の有無。

## 通常版と deskil 版の用意

- deskil 版: `plugins/deskil-dev/skills/decide/`（`flow.toml` で動く）をそのまま使う。
- 通常版: `deskil:flow-export` で `decide` を通常のスキルに戻し、別の名前（例: `decide-plain`）で置く。同じ手順から作るので、題材は同じになる。

## 試行の手順

1. 同じ状態から始める。毎回、同じコミットの作業ツリーと、同じ内容の `docs/BACKLOG.md`（todo の項目を 1 件）を用意する。
2. 新しいセッションで、通常版または deskil 版を起動し、同じ回答方針で最後まで進める。ユーザの回答は事前に台本として決めておく。
3. セッションを終えたら、記録ファイル（`~/.claude/projects/<project>/<session>.jsonl`）の場所を控える。
4. これを各版 3 回行う。順序は交互にする（通常、deskil、通常、…）。

## 集計

```
uv run shared/bench/tokens.py plain=<jsonl> plain=<jsonl> plain=<jsonl> deskil=<jsonl> deskil=<jsonl> deskil=<jsonl>
```

`--json` を付けると JSON で出力する。出力は、記録ごとの行と、版ごとの平均である。

| 列 | 意味 |
|---|---|
| input / cache_create / cache_read / output | API の使用量。1 つの応答が複数行に分かれて書かれるため、メッセージ ID ごとに 1 回だけ数える |
| total | 上の 4 つの合計 |
| turns | 応答の数 |
| tool_calls | ツール呼び出しの数 |
| tool_errors | エラーで返ったツール結果の数 |

`cache_read` は安いトークンなので、`total` だけでなく内訳も見る。

集計するのは、トライアルのセッション記録 1 ファイルだけである。サブエージェントの記録は含まないため、題材のスキルがサブエージェントを使う場合は合計が実際より小さく出る。`decide` は使わないので初版では対象外とする。

## 手順の遵守（手動の確認）

記録を読み、次を各試行で数える。

- 定められた手順の飛ばし、順序の入れ替えがあったか。
- 完了条件（項目が ready になる、または dropped になる）を満たしたか。
- 余計な質問や、手順にない作業があったか。
