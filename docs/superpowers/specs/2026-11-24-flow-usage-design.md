# flow: ステートごとのトークン使用量の記録と可視化（設計）

## 目的と背景

flow の定義（スキル）を最適化するスキルを作りたい。そのために、run の各ステートで消費したトークン量を記録し、定義の構造（ステート・遷移・visits）と並べて見られるようにする。

- トークン量はエンジンからは見えないが、Claude Code のセッションログ（jsonl）に、ターンごとの usage と時刻が残っている。`CLAUDE_CODE_SESSION_ID` 環境変数でセッションを特定できる。
- run の `history` には、ステートを抜けた時刻（`at`）が残っている。これでログをステートの区間に切り分けられる。
- ログは Claude Code が一定期間で消すため、集計結果を run の隣に保存して残す。

## ゴール

- run ごと・ステートごとに、トークン量（input / cache_create / cache_read / output）、ターン数、ツール呼び出し数、訪問回数を記録する。サブエージェント分も含める。
- 複数の run をまとめて集計し、ステートごとの平均を出せる。
- `flow graph` の Mermaid 図に、トークン量を重ねて表示できる。
- 最適化スキルが機械的に読める形（JSON）でデータを残す。

## 非ゴール

- 最適化スキル自体は、この設計に含めない（別の作業にする）。
- 実行中の予算判定・停止はしない。
- Claude Code 以外のエージェントのログには対応しない。
- 金額への換算はしない。

## 方式（選んだもの）

候補は 3 つあった。

| 案 | 内容 | 見送った理由 / 選んだ理由 |
|----|------|------|
| A | `next` のたびにログを読み、`history` へ書く | エンジンがログ形式に依存する。大きな jsonl を毎回読む。ログの書き出しが間に合わない場合がある |
| B | 時刻と session_id だけ記録し、集計は後で行う | エンジンは軽いが、集計前にログが消えるとデータを失う |
| **C** | B に加え、集計結果を run の隣に保存する | **採用**。ログ形式への依存を `usage` に閉じ込められ、ログが消えてもデータが残る |

## 設計

### 記録（エンジン側の最小変更）

- `Run` に `session_id`（`start` 時の `CLAUDE_CODE_SESSION_ID`。無ければ空）と `started_at` を足す。古い run（無い場合）は読み込みで空として扱う。
- run が終了したとき（`next` で end ステートに入ったとき）、`usage` と同じ集計を行い、`<state_dir>/<run_id>/usage.json` を書く。集計に失敗しても `next` は失敗させない（警告だけ出す）。

### 集計: `deskil flow usage <run_id>... [--save] [--json]`

- 区間: ステートの入室時刻は、前の `history` エントリの `at`（最初は `started_at`）。退室時刻はそのエントリの `at`。現在のステートは「入室〜現在」とする。
- ターンの振り分け: assistant メッセージのタイムスタンプで区間に入れる。メッセージ id ごとに usage を 1 回だけ数える（`bench/tokens.py` と同じ規則）。
- サブエージェントのログ（`<id>/subagents/agent-*.jsonl`）も、同じ時刻の規則で振り分ける。
- 保存済みの `usage.json` があり、ログが見つからないときは、保存済みの値を使う。
- 複数 run: ステートごとに「run 内の訪問を合計した値」を出し、run 間で平均する。run 数、最小、最大も出す。
- 出力: 人間向けの表（既定）と `--json`。`--save` は各 run の `usage.json` を（再）書き込みする。

### 共通部品

- `bench/tokens.py` のログ読み取りを、`shared/flow/` から使える共通モジュールに切り出し、`bench` と `usage` の両方から使う。標準ライブラリのみ（Python 3.11+）。

### 可視化: `flow graph <定義> --usage <run_id>...`

- 各ステートのノードに、平均の合計トークン量と訪問回数を併記する。
- 全ステートの合計に対する割合で、ノードに色の濃淡を付ける（Mermaid の `classDef`）。
- `--usage` なしの出力は、今と変えない。B-007 の「実行履歴の重ね表示はしない」は、この追加で置き換える。

### `usage.json` の形（案）

```json
{
  "run_id": "…", "session_id": "…", "definition": "…", "definition_hash": "…",
  "states": {
    "<state>": {"visits": 2, "input": 0, "cache_create": 0, "cache_read": 0,
                "output": 0, "turns": 0, "tool_calls": 0, "sub_total": 0}
  }
}
```

## 制約

- Python 標準ライブラリのみ。定義の形式（flow.toml）は変えない。
- run の状態ファイルは後方互換を保つ（追加の項目は省略可能）。
- 作業は `shared/` 配下の実体で行う（シンボリックリンクは編集しない）。

## 私の判断（確認してほしいもの）

- 現在のステートは「入室〜現在」として集計する。
- ステート入室時刻を前エントリの `at` とするため、`next` を呼ぶまでの待ち時間（人間の入力待ち）に出たターンは、そのステートに入る。
- 複数 run の集計は、平均・最小・最大に絞る（中央値などは足さない）。

## builder に任せること

- コマンドの引数の細部、表の列順、色の段階数。
- ログの置き場所の探し方（`~/.claude/projects/…` の規則）と、見つからないときの扱い。
- テスト（ログのフィクスチャの作り方を含む）。
