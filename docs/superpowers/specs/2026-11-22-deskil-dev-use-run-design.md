# deskil-dev で flow のコマンド実行を使う（短い設計）

## 意図と理由

B-013 で、flow の定義に `run` を書くと flow がコマンドを実行し、終了コードと出力を LLM に渡せるようになった。
deskil-dev の flow には、LLM が毎回組み立てて実行している「引数が固定のコマンド」がある。これを `run` に移し、手間とばらつき（ID の推測、lint の実行忘れ）を減らす。

## ゴール

- 引数が固定の `backlog.py` コマンドを、deskil-dev の各 flow の `run` に移す。
- そのために、定義に書く argv から、プラグイン内のスクリプトを指せるようにする。

## 非ゴール

- 分岐の判断は LLM のまま。終了コードによる自動分岐は B-003 の範囲。
- 引数がユーザーの依頼で変わるコマンド（`decide` / `impl` の `pick`）、プロジェクトごとに違うコマンド（`impl` の `verify`）、分岐を含む手順（`impl` の `prepare`）は `run` にしない。
- `cwd` の制限（定義ディレクトリの外へ出さない）は変えない。

## アプローチ

スクリプトの場所の書き方について、3 案を比べた。

| 案 | 内容 | 評価 |
|---|---|---|
| (a) `${DEF_DIR}` 展開（採用） | flow が argv の `${DEF_DIR}` を定義ファイルのディレクトリ（絶対パス）に置き換える | flow が定義の位置を知っているので確実。環境に依存しない |
| (b) `--file` を使う | `backlog.py --file` で対象を指定する | スクリプトの場所の問題が残る |
| (c) 環境変数で渡す | `start` が `CLAUDE_PLUGIN_ROOT` を flow に渡す | 呼び出し側の環境に依存し、再現性が下がる |

ユーザーが (a) を選んだ。

## 設計

### flow の変更（`shared/flow/flow.py`）

- `run` の argv の各要素にある `${DEF_DIR}` を、定義ファイルのあるディレクトリの絶対パスに置き換えて実行する。他の `${...}` は展開しない（そのまま渡す）。
- 展開は実行の直前に、確認済み ref の定義から取り出した argv に対して行う（TOCTOU 対策を維持する）。確認済み ref の argv との比較は、展開前の文字列で行う。
- run の記録と画面表示には、展開前の argv ではなく、展開後の argv を載せる。何が実行されたかが分かるため。
- `cwd` には展開を適用しない。
- `flow lint` は `${DEF_DIR}` を許す。未知の `${...}` は警告にする（誤記の検出）。
- `flow-author` の `SKILL.md` と `README.md` に `${DEF_DIR}` を書く。

### deskil-dev の flow の変更

プラグイン内のスクリプトは `${DEF_DIR}/../../scripts/backlog.py`（`skills/<name>/flow.toml` から見たパス）で指す。
作業ディレクトリは既定のまま（flow を起動した場所＝プロジェクト）なので、`docs/BACKLOG.md` はプロジェクトのものが対象になる。

| flow | ステート | run |
|---|---|---|
| add | `lint`（`fix` からの再入を含む） | `backlog.py lint` |
| add | `write` | `backlog.py next-id`（結果を見て LLM が追記する） |
| decide | `lint` | `backlog.py lint` |
| prio | `lint` | `backlog.py lint` |
| prio | `survey` | `backlog.py list` |

- プロンプトからコマンドの文言は消さない。コマンドが実行されなかった場合（`--ref` が引けない、定義が ref と違う）でも、LLM が同じコマンドを自分で実行すれば成り立つようにする。
- `lint` の分岐（ok / errors）の `when` は、「実行結果の終了コードと出力」を根拠にする文面に直す。

## 未決・ビルダーに任せる点

- インストール済みプラグインで `--ref` の確認が通るか。通らなければ上記のとおり「表示のみ」になるので、実害はないが、実行の効果は dev リポジトリに限られる。確認結果は別途バックログに残す（B-NNN）。
- `${DEF_DIR}` は、`load_definition` が解決した実パス（シンボリックリンクを解決したもの）の親ディレクトリになる。`..` はカーネルが物理パスでたどるので、動作は変わらない（実装で確認済み）。

## 進め方

1. バックログに項目を追加する（`deskil-dev:add`）。
2. `deskil-dev:decide` / `deskil-dev:impl` のフローに乗せ、ブランチと PR で進める。
