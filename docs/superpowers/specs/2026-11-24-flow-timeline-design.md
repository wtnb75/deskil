# flow: run のタイムライン表示（設計）

## 目的と背景

run の各ステートに、どれだけ時間とトークンがかかったかを、人間が一目で見比べられるようにする。見た結果から、人間と AI が一緒に改善を考えるための画面である。

- 承認（gate）の待ちが長い、または散らばっている → 承認を前半にまとめる。
- 時間が長いのにトークンが少ない → 待ちが大半。サブエージェントや実行時間を見直す。
- トークンが多く、単位時間あたりも多い → プロンプトの工夫、サブエージェント化、コンテキストの圧縮を考える。
- サブエージェントを並列にしたつもりが、実は直列だった、を見つける。

変更前後の比較は、run ID を複数並べて目で見比べる（グループ指定や差分の計算は作らない）。

前提となる既存の機能（PR #76）: `usage.json`（ステートごとの合計）、`deskil flow usage`（複数 run の平均）、`graph --usage`。

## 見た目（承認済みの見本）

見本: `docs/superpowers/specs/2026-11-24-flow-timeline-mock.html`（ダミーデータで動く単一ファイル。builder はこれを出発点にする）。

- 複数の run を縦に並べ、**同じ時間軸**で描く。
- 棒の**幅**は時間、**高さ**は 1 分あたりのトークン量。面積がトークン量になる。
- gate の待ちは、斜線の列で表す。「長い待ちを短く表示」のチェックで、待ちの幅に上限（120 秒相当）をかけ、作業を読めるようにする（短縮した待ちには本当の時間を `≈ 40m` と表示する）。
- サブエージェントを使ったステートは、点線の箱 1 つで表す。箱が**ステート全体（サブエージェントを含む）**で、一番下がそのステート自身のセッション、その上に、動いている間だけサブエージェントを薄い色で積む。同時に動くと高くなり、順番に動くと横に並ぶ。
- 各 run の見出しに、所要時間、トークン合計（サブエージェント込み）、待ちの割合を出す。
- マウスを載せる／フォーカスすると数値を出す。「Numbers per visit」の表で、訪問ごと・サブエージェントごとの数値を見られる。
- 明暗の両テーマに対応する。

## ゴール

- `deskil flow timeline RUN_ID [RUN_ID ...]` が、上の見た目の**単一の HTML ファイル**を書き出す。
- HTML は自己完結（外部の通信・外部のライブラリ・Web フォントを使わない）。ブラウザで開けばオフラインで動く。
- サブエージェントごとの時間とトークン量を、`usage.json` に記録する。
- AI が読めるよう `--json` を付ける（HTML を作らず、描画に使うデータを出す）。

## 非ゴール

- ターミナルへの文字の図（検討したが、gate の待ちが縮尺を支配して読めないため見送った）。
- 変更前後のグループ指定、差分の計算。
- 画像（PNG）や PDF への書き出し、実行中の自動更新。
- サブエージェント内で動く run、同時に動く別の run の帰属の修正（B-070）。この設計はそれを前提にせず、B-070 が直ればそのまま正しくなる。
- 金額への換算。

## 設計

### コマンド

`deskil flow timeline RUN_ID [RUN_ID ...] [-o FILE] [--open] [--json] [--state-dir DIR]`

- 既定の出力先は `./flow-timeline.html`。書いたパスを標準出力に出す。`-o -` で標準出力に HTML を出す。
- `--open` は、書いたあとに標準ライブラリの `webbrowser` で開く。失敗してもエラーにしない。
- `--json` は HTML を作らず、描画データ（下の形）を標準出力に出す。
- run ID の検証、見つからないときのエラー、`--state-dir` の扱いは `usage` に合わせる。

### データ: `usage.json` に `timeline` を足す

最上位に、訪問ごとの配列を足す（既存の `states` はそのまま）。

```json
"timeline": [
  {"state": "review", "visit": 1, "start": "…T12:32:01.120+09:00", "end": "…T12:34:31.400+09:00",
   "gate": false, "open": false,
   "input": 0, "cache_create": 0, "cache_read": 0, "output": 0, "turns": 0, "tool_calls": 0,
   "sub_total": 156000,
   "agents": [
     {"name": "agent-a1b2", "start": "…", "end": "…", "input": 0, "cache_create": 0,
      "cache_read": 0, "output": 0, "turns": 0, "tool_calls": 0}
   ]}
]
```

- 区間は `history[].at` から作る（入室は前のエントリの `at`、最初は `started_at`）。`gate` は、その `history` エントリに `approval` があるかで決める（定義を読まない）。
- 実行中の run の現在のステートは、終了を「計算した時刻」にして `"open": true` を付ける。終了済みの run の終端ステートは、区間を作らない（今までと同じ）。
- `sub_total` は、その訪問の `agents` の合計と一致させる。
- `agents`: サブエージェントのログ（`<session>/subagents/agent-*.jsonl`）を**1 ファイルずつ**、メインのログと同じ規則（メッセージ id ごとに 1 回、タイムスタンプで訪問に振り分け）で数える。同じエージェントが訪問をまたぐ場合は、訪問ごとの別の項目にする。`start` / `end` は、そのエージェントのその訪問でのターンの最初と最後の時刻（可能なら、ファイル内の最初の記録の時刻まで広げる）。
- `compute_usage` が `states` と同じ振り分けから `timeline` も作る。`usage.json` が無い、または `timeline` の無い古い `usage.json` の run は、ログが残っていれば `timeline` を計算し、無ければ `history` と `started_at` から時刻だけの `timeline`（トークンは 0 でなく「不明」を表す `null`）を組み立てる。`started_at` が空の古い run は、最初の訪問を表示しない。

### 描画データと HTML

- 描画データは `{"runs": [{"id", "note", "total_sec", "tokens", "wait_sec", "visits": [...]}]}` の形にする。`visits` は `usage.json` の `timeline` から、秒数とトークンを計算して作る。`note` は run の定義のパス（`definition`）の末尾を出す。
- HTML は、見本の CSS と JS を雛形にして、`<script type="application/json">` に描画データを埋め込む。埋め込みでは `</` を `<\/` にエスケープする（run や状態の名前に `</script>` が入っても壊れない）。
- JS の描画は見本のものを使い、ダミーのデータの部分だけを埋め込みデータの読み込みに替える。外部の URL（フォントを含む）は使わず、システムのフォントだけにする。
- 値が `null`（トークン不明）の訪問は、棒を描かず「トークン不明」と表示する。

### 構成

- `shared/flow/usage.py`: `timeline` の生成、サブエージェントごとの集計、描画データの作成。
- `shared/flow/timeline.py`（新規）: HTML の雛形と、`render_html(data: dict) -> str`。`pyproject.toml` の `py-modules` に足す。
- `shared/flow/flow.py`: サブコマンドの登録と分岐だけ。
- README に、コマンドと読み方を数行で足す。見本の HTML は、設計書と一緒に `docs/` に残す。

## 制約

- 標準ライブラリのみ。`usage.json` の既存の項目は変えない（後方互換）。
- 出力の HTML に、`http://` または `https://` で始まる外部の参照を入れない。
- コメント・エラーメッセージ・README は英語。HTML 内の表示文言も英語（見本のとおり）。

## 採用しなかった案

- ターミナルの文字の図: gate の待ちが縮尺を支配し、作業が 1 桁以下になって読めない。
- `usage --timeline`: `usage` は平均の集計で、タイムラインは run ごとの表示。
- `graph` に時間を足す: Mermaid では訪問の順序や待ちの偏りが見えない。
- サブエージェントを下の別の段に出す案: 親の箱がサブエージェントのトークンを含まず、ステートの重さが過小に見える。

## 私の判断（確認してほしいもの）

- 既定の出力先は `./flow-timeline.html`。ブラウザで開くのは `--open` のときだけ。
- HTML は自己完結で、外部の通信やフォントを使わない（オフライン・機密の保護のため）。
- サブエージェントの数値は、訪問ごとに分けて持つ（訪問をまたぐ場合は 2 項目になる）。
- 古い run でトークンが分からない訪問は、`null` を使って「不明」と表示する。0 とは区別する。
- 待ちの短縮は、既定ではオフ。幅の上限は 120 秒相当。

## builder に任せること

- サブエージェントの表示名（サブエージェントのログやその隣のファイルに、種類や説明が入っているか確認し、あればそれを使う。無ければファイル名）。
- 色の割り当て、層の濃さ、幅の端数の丸め、ステートが 6 色を超えたときの色の使い回し。
- テスト（時刻の境界、複数訪問、訪問をまたぐサブエージェント、`started_at` が空の run、実行中の run、`</script>` を含む名前、外部参照が無いこと、`--json`）。HTML の描画そのものは、実際の run でブラウザを開いて確認する。
