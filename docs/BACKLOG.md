# バックログ

初版では「やらない」と決めたアイデア・未確認事項を積む場所。

## 運用ルール

- 初版の対象外にしたら、その場でここに追記する（設計書の「非ゴール」には、ここへの ID 参照を書く）。
- 1 項目 = 1 見出し。ID は `B-NNN` の連番で、欠番は詰めない。
- 状態は次の 4 種。作業中の中間状態は持たない（途中の状態でマージされることはないため）。

| 状態 | 意味 |
|---|---|
| `todo` | 積んだ直後。判断が必要なものも、ここに置く。 |
| `ready` | 判断が済み、実装できる。判断の結果を `判断` に書いてから移す。 |
| `done` | 実装した。 |
| `dropped` | やめた。理由を `判断` に書く。 |

- `done` / `dropped` にした項目は、`## done / dropped` へ移す（削除しない）。
- 項目の書式（値は 1 行で書く）:

```
### B-NNN タイトル
- 状態: todo
- 優先度: P2
- 依存: B-009, B-011
- 追加: YYYY-MM-DD
- 背景: なぜ積んだか（初版で見送った理由）
- 概要: 何をするか
- 判断: （ready / dropped にするとき、決めた内容や理由を書く）
- 完了: YYYY-MM-DD
- PR: #N
```

| 欄 | 意味 |
|---|---|
| `優先度` | `P1`（高）/ `P2`（中、既定）/ `P3`（低）。`todo` / `ready` では必須。並べ替えはせず、欄で表す。 |
| `依存` | 任意。先に `done` になっているべき項目の ID（カンマ区切り）。未完了、`dropped`、存在しない ID があると「ブロック中」で、実装には進めない。 |
| `完了` / `PR` | `done` のときだけ書く（`dropped` には `PR` を書かない）。`backlog.py archive --done --pr N` が書く。 |

- 一覧・採番・書式検査・状態の変更は `shared/backlog/backlog.py`（`list` / `show` / `next-id` / `lint` / `set` / `archive`）で行う。並びは「状態（ready が先）→ 優先度 → ID」で、`list` が表示する。

### B-013 flow: 定義に書いたコマンドの実行と結果の受け渡し
- 状態: done
- 優先度: P2
- 追加: 2026-11-22
- 背景: 初版の flow は、状態の案内だけをして、コマンドの実行は LLM に任せている。テストやビルドなど、決まったコマンドも LLM が毎回組み立てて実行するため、手間とばらつきがある。
- 概要: 定義ファイルのステートにコマンドを書けるようにし、flow がそれを実行して、終了コードと出力を LLM に渡す。分岐の判断は LLM のままにする（終了コードで分岐を決める B-003 とは別。組み合わせは可能）。未決: (1) コマンドの書式（文字列か配列か、シェルを通すか）。(2) 出力が長いときの切り詰め方、標準出力と標準エラーの扱い。(3) タイムアウトと作業ディレクトリ。(4) 実行前の承認の扱い。(5) 実行結果を run の記録に残すか。(6) 定義ファイルをどのブランチから読むか。
- 判断: (1) コマンドは配列のみ、シェルは通さない（パイプが必要なら `["sh", "-c", ...]` を明示）。(2) 標準出力と標準エラーを分け、それぞれ末尾優先で切り詰める（既定 100 行、定義で上書き可）。切り捨てた行数を示し、全文は run ディレクトリに保存する。(3) タイムアウトは既定 300 秒で、ステートごとに `timeout` で上書きできる。超過は終了コードをタイムアウトとして返す。作業ディレクトリは既定で flow を起動した場所、定義の `cwd`（定義ファイル基準）で変えられる。(4) 承認なしで実行する（実行は確認済み ref の定義に限るため）。(5) 終了コードと切り詰め済みの出力を run の記録に残す。(6) `start` に `--ref`（既定 `main`）を持たせ、その ref の定義だけでコマンドを実行する。作業ツリーの定義はコマンド実行を無効にし、表示のみ行う。（2026-11-22。この方針は、以前の「方針のみ」の判断を確定させたもの。）
