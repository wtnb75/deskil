# バックログ

初版では「やらない」と決めたアイデア・未確認事項を積む場所。

## 運用ルール

- 初版の対象外にしたら、その場でここに追記する（設計書の「非ゴール」には、ここへの ID 参照を書く）。
- 1 項目 = 1 見出し。ID は `B-NNN` の連番で、欠番は詰めない。
- 状態は次の 4 種。作業中の中間状態は持たない（途中の状態でマージされることはないため）。

| 状態 | 意味 |
|---|---|
| `todo` | 積んだ直後。判断が必要なものも、ここに置く。 |
| `ready` | 判断が済み、実装できる。判断の結果を `判断` に書いてから移す。 |
| `done` | 実装した。 |
| `dropped` | やめた。理由を `判断` に書く。 |

- `done` / `dropped` にした項目は、`## done / dropped` へ移す（削除しない）。
- 項目の書式（値は 1 行で書く）:

```
### B-NNN タイトル
- 状態: todo
- 優先度: P2
- 依存: B-009, B-011
- 追加: YYYY-MM-DD
- 背景: なぜ積んだか（初版で見送った理由）
- 概要: 何をするか
- 判断: （ready / dropped にするとき、決めた内容や理由を書く）
- 完了: YYYY-MM-DD
- PR: #N
```

| 欄 | 意味 |
|---|---|
| `優先度` | `P1`（高）/ `P2`（中、既定）/ `P3`（低）。`todo` / `ready` では必須。並べ替えはせず、欄で表す。 |
| `依存` | 任意。先に `done` になっているべき項目の ID（カンマ区切り）。未完了、`dropped`、存在しない ID があると「ブロック中」で、実装には進めない。 |
| `完了` / `PR` | `done` のときだけ書く（`dropped` には `PR` を書かない）。`完了` は必須で、`backlog.py archive --done` が書く。`PR` は任意で、`--pr N` を付けたときだけ書く（`impl` は PR を作る前に `done` にするので付けない）。 |

- 一覧・採番・書式検査・状態の変更は `shared/backlog/backlog.py`（`list` / `show` / `next-id` / `lint` / `set` / `archive`）で行う。並びは「状態（ready が先）→ 優先度 → ID」で、`list` が表示する。
